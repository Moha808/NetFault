# NetFault — Network Fault Reporting and Resolution Management System

Final-year project (HND II, Networking and Cloud Computing). A lightweight
web app where staff report network faults and admins triage, update, and
resolve them. Two roles only: **User** and **Admin** — no separate
technician tier, keeping auth simple.

## Stack
- React 18 + Vite
- React Router
- Supabase (Auth + Postgres + Row Level Security)
- Deployed on Vercel

## 1. Upload to GitHub
1. Unzip this folder anywhere on your PC/phone (e.g. with a file manager app).
2. Go to github.com → **New repository** → give it a name (e.g. `netfault`) → Create.
3. On the new repo's page, click **uploading an existing file**.
4. Drag the *contents* of the unzipped folder in (not the folder itself) —
   select everything inside `fault-report-system/` and drop it.
5. Scroll down, add a commit message like "Initial commit", click **Commit changes**.

That's it — no git command line needed. `.gitignore` is already included so
`node_modules` and `.env` won't matter even if you accidentally have them locally.

## 2. Supabase setup
1. Create a new project at supabase.com.
2. Open the SQL editor and run `supabase/schema.sql` in full.
3. Sign up through the app once (see below), then in the SQL editor run:
   ```sql
   update public.profiles set role = 'admin' where email = 'you@example.com';
   ```
   That account is now your admin login.

## 3. Local setup (optional — only if you want to run it on a laptop)
```bash
npm install
cp .env.example .env
# fill in VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY
# (Project Settings → API in your Supabase dashboard)
npm run dev
```

## 4. Deploy to Vercel
1. In Vercel, **Add New → Project** → Import the GitHub repo you just created.
2. Add two env vars in Vercel's Project → Settings → Environment Variables:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. Deploy — Vercel auto-detects Vite. `vercel.json` (included) fixes page
   routing so `/login`, `/register`, etc. work on direct refresh.

## Roles
- **User** — register, log in, submit fault reports, track status, edit profile
- **Admin** — view all reports, update status/priority, add resolution notes,
  manage categories, manage users (activate/deactivate, promote to admin)

## Fault lifecycle
`Pending → In Progress → Resolved → Closed`

## Project structure
```
src/
  components/     Navbar, Badge, ProtectedRoute
  context/        AuthContext (session + profile + role)
  lib/            supabaseClient
  pages/
    Home, Login, Register
    user/         Dashboard, ReportFault, MyReports, ReportDetail, Profile
    admin/        Dashboard, AllReports, ReportDetail, ManageCategories, ManageUsers
supabase/
  schema.sql      Tables, enums, triggers, RLS policies
vercel.json       SPA routing fix for Vercel
```

## Notes for the write-up
- RLS enforces the role split at the database level, not just in the UI —
  worth a paragraph in your project report under "Security Implementation."
- The `fault_updates` table gives you a free audit trail / timeline feature
  for the demo without extra work.
- Ticket numbers (`FR-1000`, `FR-1001`, …) are generated by a Postgres
  sequence, not client-side, so they can't collide.
